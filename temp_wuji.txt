# 祖龙“无级变速”会话执行规划

## Summary
可以去掉“闲聊 / 复杂任务 / 不知道 / 恢复任务”这层硬分类。保留内部评分，但不再让标签决定固定管道。

新的核心是：**每一轮对话都走同一个自适应会话执行器**。它根据内容和上下文动态调节执行强度：短聊就快速回答；需要记忆就召回图记忆；需要看项目就读文件；需要改代码就进入计划和审批；任务变长就自动创建任务图并持续汇报。

## Key Changes
- 把硬路由改成“执行强度评分”。
  - 不再输出 `small_chat/general_chat/coding_task/resume_task` 作为主决策。
  - 新增内部评分：`记忆需求`、`工具需求`、`代码需求`、`计划需求`、`风险等级`、`持续任务关联度`、`后台执行需求`。
  - 用户看不到分类标签，只看到自然反馈：例如“我先看一下项目结构”“这一步需要修改文件，等你确认”。

- 新增统一执行档位，但它不是分类。
  - 0 档：直接对话，快速回复。
  - 1 档：带记忆对话，召回 MemoryGraph。
  - 2 档：只读工具，查文件、搜代码、看状态。
  - 3 档：计划模式，生成步骤、风险、待确认项。
  - 4 档：执行模式，改文件、跑命令、写入 TaskGraph。
  - 5 档：长任务后台执行，持续心跳、可暂停、可恢复。
  - 同一轮可以升档或降档，例如先闲聊，发现用户要改项目后升到计划和执行。

## Implementation Changes
- 改造 `D:\AI\project\zulong_beta5\zulong\launcher\conversation_orchestrator.py`。
  - `RouteDecision.route` 保留兼容，但统一设为 `adaptive_turn`。
  - 新增 `TurnProfile`：保存各项评分、推荐档位、是否需要 IDE、是否需要任务图、是否需要审批。
  - `_classify()` 改为 `_score_turn()`，不再返回固定类别，而是返回连续评分和原因。
  - 语音匹配、会话关联、TaskGraph 关联仍保留，但都作为“上下文信号”，不是硬分类。

- 改造 `D:\AI\project\zulong_beta5\zulong\launcher\web_chat_router.py`。
  - `_handle_chat_message()` 不再根据 `decision.route` 分叉。
  - 所有输入统一进入 `AdaptiveConversationRuntime.start_turn(...)`。
  - 原 `_chat_via_engine()`、`_start_coding_task_from_web()` 变成 runtime 内部可选择动作。
  - 每轮固定先发 `turn:accepted`，随后按档位发 `task:progress`。

- 改造 IDE/L2 执行侧。
  - `ide_fc_runner.py` 的 `_detect_ide_intent()` 改为生成执行画像，不再返回 `chat/complex/resume`。
  - `ide_tool_registry.py` 的 `get_combined_tool_definitions_for_intent()` 改成按执行画像发工具：低档只给记忆/只读工具，高档才给写文件/终端/任务图工具。
  - `intent_prompt_builder.py` 保留为兼容层，逐步替换成“自适应会话提示词”：告诉模型可按需要升档，而不是先判断类别。

- TaskGraph 改为“按需出现”。
  - 普通闲聊不建图。
  - 当计划需求、长期跟踪需求、代码修改需求、恢复关联度达到阈值时，自动创建或挂接 TaskGraph。
  - 用户说“继续刚才那个”时，不走 `resume_task` 分类，而是持续任务关联度升高，自动召回 MemoryGraph 和 TaskGraph。

- MemoryGraph 作为持续上下文底座。
  - 每轮都可轻量检索，但按评分决定检索深度。
  - 执行过程中的计划、审批、代码差异、测试结果、阻塞原因都写成记忆事件。
  - 下次对话靠图记忆判断是否延续旧任务，而不是靠用户命中某个“恢复任务”类别。

## Behavior Examples
- “你好”：0 档，直接自然回复，不建任务图。
- “刚才那个任务做到哪了”：持续任务关联度高，召回 MemoryGraph + TaskGraph，回答当前进度。
- “这个项目为什么启动不了”：升到 2 档，先读项目文件和终端信息，再汇报发现。
- “帮我重构任务执行模块”：升到 3 档，先给计划和风险；确认后进入 4 档。
- “可以自动执行这些测试”：加入白名单，同类测试命令后续自动执行，但写文件仍看权限。

## Test Plan
- 简短闲聊测试：不创建 TaskGraph，1 秒内回复。
- 连续变速测试：同一会话从闲聊升到代码分析，再升到文件修改审批。
- 降档测试：复杂任务中用户问一句解释性问题，只回答解释，不强行继续 FC 循环。
- 恢复测试：用户模糊说“继续刚才那个”，系统能通过 MemoryGraph 找到相关任务。
- 工具门控测试：低评分时不给写文件工具，高评分且用户确认后才开放。
- 事件测试：每次升档、等待、审批、阻塞、完成都有可见进度事件。
- 兼容测试：旧前端仍能接收 `route` 字段，但实际值统一为 `adaptive_turn`。

## Assumptions
- 内部保留评分和档位，方便调试和记忆沉淀；用户界面不显示机械分类。
- 旧的 `chat/complex/resume` 先保留为兼容字段，逐步废弃。
- 祖龙的目标不是“分类更准”，而是“根据对话自然调节执行强度”。
