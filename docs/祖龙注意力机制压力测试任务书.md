# Markdown 知识库管理系统 — 祖龙三核心机制压力测试任务书

> **测试目标**: 注意力窗口（GLOBAL/FOCUS/SINGLE_CHAIN）切换、CircuitBreaker 熔断检测、L2 Backup 降级

## 1. 项目概述

开发名为 **md-knowledge-base** 的 Markdown 知识库管理系统。

系统功能：扫描目录下的 Markdown 文件 → 解析为结构化知识节点 → 构建知识图谱（标签关联、文档链接、自动分类）→ 全文搜索引擎 → REST API → CLI 交互 → 数据导出。

项目根目录：`D:\AI\zulong_stress_lab\md_knowledge_base`

## 2. 技术栈

| 领域 | 选型 |
|------|------|
| 语言 | Python 3.10+ |
| Markdown 解析 | markdown-it-py 或 mistune |
| 知识图谱 | networkx（内存图）+ JSON 持久化 |
| 全文搜索 | 自建倒排索引 + TF-IDF（不依赖 ES） |
| REST API | FastAPI + uvicorn |
| CLI | click 或 typer |
| 数据导出 | JSON/CSV（标准库） |
| 测试 | pytest + pytest-asyncio |
| 配置 | pyproject.toml + requirements.txt |

## 5. 预期注意力切换验收路径

> 注意：动态注意力验收不再以固定工具名映射作为主口径。
> `exec_write_file` / `exec_run_command` 等只代表压力测试中的工作负载事件，不能要求“调用某工具名必然切换到某模式”。
> 主验收口径应为：**上下文压力阈值触发 L2 动态注意力评估，LLM 根据当前任务、TaskGraph 节点、覆盖缺口和证据状态自主选择 GLOBAL / FOCUS / SINGLE_CHAIN，并按需注入必要上下文**。

```
[GLOBAL]      task_create_plan() + task_add_node ×10 + task_add_dependency ×14
[GLOBAL]      task_view_overview()  ← 确认规划
    ↓
[上下文压力/当前节点明确] LLM 自主选择 FOCUS  ← 注入 T1 相关节点、依赖和证据
[单链执行/调试压力上升] LLM 自主选择 SINGLE_CHAIN  ← 注入当前推理链必要上下文，暂排无关分支
[子任务完成/跨分支复核] LLM 自主选择 FOCUS 或 GLOBAL  ← 按需重新注入其他上下文
    ↓ (重复 T2-T8 的压力阈值监控 + LLM 自主注意力选择循环)
    ↓
[T9 调试压力点] 多轮测试/修复产生上下文压力与覆盖缺口
    ↓ (CircuitBreaker 可能在此阶段触发 YELLOW/RED)
    ↓
[RED-2]       动态注意力重选 + 按需注入，不做简单上下文压缩
    ↓
[RED-3]       便签锚定当前节点 + 受限注意力重选
    ↓
[GLOBAL]      T10: 完成前覆盖复核 + submit_final_answer()
```

## 6. CircuitBreaker 验证标准

| 验证项 | 预期行为 |
|--------|---------|
| YELLOW 警告 | 注入"尽快总结"提示，继续执行 |
| RED-1 纠偏 | 若存在未完成节点、未处理失败或 TaskSpec 覆盖缺口，优先注入纠偏提示并继续修正 |
| RED-2 动态注意力 | 不压缩上下文；触发 LLM 基于压力、当前节点、覆盖缺口和证据状态重新选择注意力模式，并按需注入必要上下文 |
| RED-3 受限恢复 | 第三次 RED 先把当前证据、未完成项、失败原因写入便签并挂到当前节点；随后收走普通执行工具，只保留便签/记忆落盘能力与注意力切换能力，强制进行一次注意力重选 |
| 覆盖感知收束 | 受限恢复后，覆盖通过则允许最终总结；覆盖不通过只能输出 partial/blocked summary，不能伪完成 |
| 连续5次YELLOW | 自动升级为 RED |
| RED + 未完成节点 | 纠偏逻辑将 RED 转为工具纠偏而非强制停止 |

## 7. L2 Backup 验证标准

| 验证项 | 预期行为 |
|--------|---------|
| CORE 超时 (>300s) | 切换到 BACKUP 模型 |
| BACKUP 成功 | 返回回复 + "[此回复由备用模型生成]" 后缀 |
| BACKUP 也超时 | SmartDegradationHandler 生成智能降级回复 |
| CORE/BACKUP 同一模型 | 跳过备用调用，直接静态降级 |

**主动测试方法**: 临时将 `l2_inference.timeout.core` 设为 5 秒，发送任务观察降级链。

## 8. 执行约束

1. 严格按依赖顺序执行，不得跳步
2. 每个子任务完成后调用 `task_mark_status(completed)`
3. 每完成 2-3 个子任务调用 `task_view_overview()` 确认进度
4. 遇到错误必须修复后重试，不得跳过
5. 所有代码必须写入文件，不得只在回复中展示
6. 最终调用 `submit_final_answer()` 包含验收报告
