### 2.2 核心设计模式

| 模式 | 实现位置 | 说明 |
|------|---------|------|
| **单例模式** | `get_memory_graph()` | 全局唯一 MemoryGraph 实例 |
| **工厂模式** | `memory_graph_factory.py` | 根据配置创建不同类型记忆图 |
| **适配器模式** | `graph_adapters.py` (2,255行) | 各子系统 → 图节点/边适配 |
| **策略模式** | `hybrid_search_config.py` | 混合检索策略(向量+BM25) |
| **观察者模式** | `hot_update_engine.py` | 热更新事件通知 |
| **装饰器模式** | `rollback.py` | 操作回滚装饰器 |
| **分片模式** | `sharded_memory_graph.py` | 时间维度分片存储 |

### 2.3 关键算法

| 算法 | 位置 | 复杂度 |
|------|------|--------|
| BFS 扩散激活 | `MemoryGraph._bfs_discover()` | O(V+E) |
| 赫布学习 (边权增强) | `MemoryGraph._hebbian_update()` | O(1) / 共激活 |
| 艾宾浩斯衰减 | `MemoryGraph._apply_forgetting()` | O(N) |
| FAISS 向量检索 | `MemoryGraphHybrid.search_and_discover()` | O(log N) |
| 双路径并行检索 | 热 BFS + 冷 FAISS (`asyncio.gather`) | O(V+E) ∥ O(log N) |
| 混合检索 (向量0.7+BM25 0.3) | `hybrid_search_config.py` | O(N) |

### 2.4 三维标签体系

```
Temperature: HOT(近期访问) / WARM(中等) / COLD(长期未访问)
Importance: 6级 (trivial < normal < identity < fact < important < must_remember)
TimeScope: RECENT(24h内) / NON_RECENT(超过24h)
```

## 三、关键发现

### 3.1 架构亮点

1. **分层清晰**: 存储层(LMDB+FAISS) → 图谱层(NetworkX) → 检索层(BFS+FAISS) → 工具层(FC) 四层分离
2. **双路径检索**: 热路径 BFS (<50ms) + 冷路径 FAISS (<200ms) 并行，兼顾速度与召回
3. **混合存储**: 拓扑索引(NetworkX) + 属性存储(LMDB) + 向量索引(FAISS) 三层分离，各司其职
4. **自适应衰减**: 艾宾浩斯遗忘曲线 + 赫布学习增强，模拟生物记忆机制
5. **完整工具链**: 4个 FC 工具暴露 53 个公开方法，覆盖记忆全生命周期

### 3.2 潜在风险

1. **MemoryGraph 单文件过大**: `memory_graph.py` 达 3,564 行，建议拆分
2. **graph_adapters.py 复杂度高**: 2,255 行，适配器逻辑过于集中
3. **NetworkX 内存限制**: 纯内存图结构，节点数超过 10 万时可能 OOM
4. **JSON 持久化性能**: 当前使用 JSON 序列化，大图时 I/O 瓶颈

### 3.3 改进建议

1. 将 `memory_graph.py` 拆分为 `graph_core.py` / `graph_bfs.py` / `graph_hebbian.py` / `graph_persistence.py`
2. 将 `graph_adapters.py` 按子系统拆分为独立适配器文件
3. 考虑引入 RocksDB 替代 JSON 持久化
4. 为 FAISS 索引增加增量更新机制（当前需全量重建）
