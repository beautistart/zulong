# 任务生命周期汇报与用户交互优化方案

> 对齐最高指导文档：`TSD/祖龙 (ZULONG) 机器人系统技术规格说明书 (TSD)1.7.txt` §23。
> 本方案仅优化前端交互与执行事件表达，不改变 L0-L3 分层、L1-B -> L2 -> FC 主链、EventBus/SharedMemory/WebSocket 边界。

## 1. 目标

祖龙现有实现已经具备 `InteractionPayload`、`task:plan`、`task:summary`、`INTERACTION_EVENT`、TaskGraph 与 MemoryGraph 写入基础，但用户可感知体验仍偏“技术状态卡片”。本方案把执行过程统一为 TSD §23.3 的三层汇报：

1. 启动说明：用户发起任务后，立即说明“已接收、要做什么、准备怎么做、会用哪些能力、为什么这样安排”。
2. 中期进度：工具调用开始、工具结果、模型等待、任务图状态变化时，用 `action/observation/progress` 汇报。
3. 结束总结：任务完成、失败、取消时，汇总完成项、验证项、未完成项、风险、下一步和记忆变化。

v2.9.3 追加约束：用户可见进度采用清单式表达，不使用百分比或进度条作为主反馈。清单项来自计划、工具账本、TaskGraph 或 summary，完成一项就标记一项，状态限定为 `pending/running/completed/blocked/failed`。

v2.9.4 追加约束：用户显式提出“不要工具/最多 N 个工具/不超过 N 次工具调用”时，必须在后端执行边界硬控。预算为 0 时不向 L2 暴露工具定义；预算用尽时拦截超额工具调用、移除后续工具定义，并通过 `progress_items` 告知用户转入已有信息总结。旧“思考过程”只作为默认折叠的“执行明细”保留。

v2.9.5 追加约束：客户端大消息问题只能通过建连摘要、按需加载和 WebSocket 分片解决，不能用业务裁剪隐藏 MemoryGraph/执行事件。前端必须按 `snapshot_id/chunk_index/chunk_total` 合并完整快照，分片批次不表示节点或边的业务上限。

## 2. 参考项目结论

### 2.1 OpenHands

OpenHands 的关键是“事件账本 + UI 压缩视图”：

- `ActionEvent` 表示要执行的动作，包含 `thought`、`tool_name`、`tool_call_id`、`security_risk`、`summary`。
- `ObservationEvent` 表示动作结果，通过 `action_id/tool_call_id` 与 Action 配对。
- 前端保留完整 `events`，同时生成 `uiEvents`；Observation 到达后原位替换 Action，避免工具调用和结果重复刷屏。
- `summary` 可作为工具卡片的人类可读标题，`TaskTrackerAction/Observation` 可呈现计划状态。

### 2.2 Codex/.codex

Codex 的关键是“工具卡片之外的可见叙事层”：

- 多步骤任务先给简短开始反馈。
- 执行中用短句说明当前正在读取、修改、验证什么。
- 最终总结聚焦修改内容、验证结果、未完成风险，不把原始日志完整丢给用户。
- 本地规则、会话记录和记忆让后续任务能延续偏好与项目约束。

## 3. TSD 对齐原则

本次优化必须严格遵守 TSD §23：

- `InteractionPayload.kind` 只能使用 `plan/action/observation/approval/progress/summary/user_interject`。
- 工具调用开始必须发 `action + thought`；工具调用结束必须发 `observation`。
- 长时间无事件或状态变化必须发 `progress`。
- 完成时必须发 `summary`，包含 `completed_items/verified_items/pending_items/risks_summary/next_step/memory_changes`。
- 进度必须优先发 `progress_items`，`progress` 数值字段只保留为旧端兼容，不在 Web 主会话中显示百分比。
- 用户显式工具预算是执行硬边界，不得只依赖 prompt 让模型自觉遵守；硬控仍位于 L2/FC 执行边界，不改变 L1-B -> L2 -> FC 主链。
- 完整调试轨迹不作为默认用户感知；主界面优先展示 plan/action/observation/progress/summary，详细执行轨迹折叠为“执行明细”。
- MemoryGraph 传输保护属于 WebSocket 层，不得改变执行记忆和审计数据完整性；建连只推 summary，完整图谱在用户进入图谱视图或显式请求时分片下发。
- 执行事件不得只停留在日志或 DOM，必须进入 `InteractionStore -> MemoryGraph -> ExperienceStore` 闭环。

## 4. 代码实施计划

### P0：协议与体验闭环

1. 后端统一 `InteractionPayload` 枚举。
   - 将历史 `state` 归一为 `progress`。
   - 将历史 `user_adjustment` 归一为 `user_interject`。
   - 所有 payload 自动补 `protocol_version/interaction_id/pair_id/turn/event_type`。

2. 后端生成可用的结束总结。
   - 基于 `self._execution_events`、`state.tool_results_buffer`、TaskGraph 进度和 MemoryGraph diff 汇总。
   - 同时输出 TSD 字段和旧前端兼容字段。

3. 前端兼容 TSD summary 字段。
   - `completed_items` -> 完成。
   - `verified_items` -> 验证。
   - `pending_items` -> 未完成。
   - `risks_summary` -> 风险。
   - `memory_changes` -> 记忆变化。

4. 启动说明改为面向用户的话术。
   - 内部 L1-B/L2 术语保留在 detail 或调试卡片中，不作为第一感知标题。

5. 清单式进度协议。
   - `plan` 事件从 `plan_steps` 派生 `progress_items`。
   - `action/observation` 事件用同一 `pair_id` 更新对应工具项状态。
   - `summary` 事件把完成项、验证项、未完成项压缩成最终清单。
   - Web 主界面不展示 `进度: xx%`、`总体进度: xx%` 或对话内进度条。

6. 工具预算硬控。
   - 新增 `zulong/l2/tool_budget.py` 解析用户原文中的显式预算。
   - `InferenceEngine._call_l2_once` 在预算为 0 时移除工具定义。
   - `FCRunner` 与 `IDEFCRunner` 在执行前裁剪/拦截超额 tool_call，记录已用工具数。
   - 预算命中时注入收敛提示，后续模型调用不再暴露工具定义。
   - Web 通过 `progress_items` 显示“已达到工具上限，转入总结”。

7. MemoryGraph 大消息分片。
   - WebSocket 建连阶段只推 `summary` 统计，不主动推完整图谱。
   - 完整图谱通过 `snapshot_id/chunk_index/chunk_total/is_last_chunk` 多帧发送。
   - 前端合并同一 `snapshot_id` 的节点、边和 `execution_view`，不丢弃执行事件。

### P1：OpenHands 式事件压缩

1. 以 `pair_id/tool_call_id` 作为前端原位更新主键。
2. 同一个工具调用的 Action 与 Observation 使用同一个 `pair_id`。
3. 工具结果卡片不重复追加，除非是不同 `pair_id`。
4. 任务图进度卡只维护一个清单快照，避免刷屏。
5. 旧调试轨迹默认折叠为“执行明细”，不在最终总结后展开刷屏。

### P2：经验化与评测

1. 从 summary 和 execution ledger 形成任务执行经验。
2. 增加测试场景：简单对话、复杂任务、工具调用、启动反馈、中途汇报、结束总结、记忆写入、压力持久化。
3. 后续可增加 summary 质量评分：必须包含完成项、验证项、风险和下一步。

## 5. 验收口径

1. 用户发起任务后 1 秒内可见启动说明或接收反馈。
2. 每个工具调用至少有一次 `action` 和一次 `observation`。
3. 模型等待或长任务执行期间有 `progress`，不再出现非 TSD `kind=state`。
4. 完成时 `task:summary` 与 `INTERACTION_EVENT(kind=summary)` 均包含 TSD summary 字段。
5. 前端能渲染完整 summary，不再只显示“模型已生成最终回复”。
6. 前端进度反馈显示为清单，完成项有明确标记，不出现百分比主反馈。
7. 用户要求“最多两个工具”时，后端最多执行两个工具；第三个及之后的 tool_call 被拦截并转入总结。
8. 最终回答末尾不默认展开几十条调试步骤；执行轨迹可手动打开“执行明细”查看。
9. 建连阶段不会因完整 MemoryGraph 超大帧断连；进入记忆图谱后能分批接收并合并完整节点、边与 `execution_view`。
10. Python 语法检查通过，关键前端脚本静态检查通过。
