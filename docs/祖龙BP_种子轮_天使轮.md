### 所属行业 / 赛道

**AI 基础设施 / Agent 中间件 / 开发者工具（DevTools）**

### 目标客户画像

**核心用户：**

- **A 类：AI Agent 开发者 / 创业公司** — 正在构建聊天机器人、编程助手、客服 Agent 等智能体产品，需要长期记忆能力但不想从零研发
- **B 类：企业 AI 平台团队** — 大型企业内部部署多 Agent 系统（如自动化运维、智能审批），需要 Agent 间共享记忆和上下文隔离
- **C 类：编程工具厂商** — 如 Cursor/Copilot 类产品的开发者，需要让代码助手记住项目架构、历史决策、修复经验

**用户所处阶段特征：**

- 已有 Agent 产品或框架，但记忆能力仅靠上下文窗口硬塞，**容量有限、信息遗忘率 > 80%**（记不多）
- 尝试过 RAG/向量数据库方案，但**检索结果碎片化、缺乏关联推理**，Agent 记住了错误的信息却不自知（记不准）
- 会话结束后记忆归零，跨会话无法延续上下文；记忆越积越多却**没有遗忘和更新机制**，旧信息干扰新决策（记不久）

### 投资亮点

1. **全市场唯一的图算法驱动记忆引擎**：MemoryGraph 是业界首个工程化落地的异构记忆图谱（赫布学习 + 艾宾浩斯衰减 + BFS 扩散检索），比学术界 HeLa-Mem 论文早 2 年实现产品化，竞品（Mem0/Zep）均采用平面向量方案，无图算法能力。

2. **切入 AI 最热赛道的基础设施层**：2025-2026 年全球 AI Agent 开发者超 500 万人，每个 Agent 都需要记忆层，但 90% 的团队仍在"用 prompt 硬塞上下文"——这是一个**刚需、高频、无标准答案**的空白市场。

3. **"卖铲子"模式 + MCP 生态红利**：以 SDK/API + MCP Server 形态交付，不做终端产品、不与下游竞争，MCP 协议已成为 Agent 工具集成的事实标准（Anthropic 推动），祖龙可在一周内接入 Claude Code/Cursor/Windsurf 等全部主流编程工具。

## 二、痛点与解决方案

> 把真实痛点和产品方案讲清楚，避免只写口号

### 1. 目标用户痛点

> *AI Agent 的记忆困局：记不多、记不准、记不久*

| 痛点 | 一句话 | 具体表现 | 现有方案的致命缺陷 |
|------|--------|---------|-------------------|
| **P1 记不多** | Agent 的记忆容量有天花板 | 上下文窗口硬塞，受 token 上限制约（主流模型 128K token），超出部分直接丢弃；复杂项目中数百个文件、数千条历史决策，Agent 只能"看到冰山一角" | Mem0/LangMem 等方案通过摘要压缩扩大容量，但**压缩必然丢信息**——10 句话压成 1 句，关键细节被抹掉 |
| **P2 记不准** | Agent 记住了错误的或无关的信息 | 向量检索（RAG）按语义相似度召回，但"相关"≠"正确"——用户说"上次那个 bug"，RAG 返回 5 个含"bug"的段落，却找不到真正关联的那次修复记录；更危险的是**矛盾记忆并存**——用户偏好从 A 改为 B，两条记录同时存在，Agent 无法判断哪个有效 | 全行业记忆方案均为**平面检索**（向量/关键词），缺乏结构化关联推理，无法区分"相关"和"真正有关" |
| **P3 记不久** | Agent 的记忆没有时间维度 | 会话结束记忆归零，每次对话都从零开始；即使做了持久化，记忆也**没有遗忘和更新机制**——3 个月前的过时信息和今天的新事实权重相同，旧记忆持续干扰新决策；同时，高频使用的关键记忆得不到加强，和冷门记忆混在一起 | Mem0/Zep 的记忆是**只增不减的平面列表**，无衰减、无加强、无时间戳仲裁，记忆越多噪声越大 |

### 3. 解决方案

> *三个痛点，三把钥匙——MemoryGraph 的核心算法逐一击破*

#### 解决「记不多」：异构记忆图谱 + 分层存储

**核心机制**：记忆不再塞进上下文窗口，而是存储在独立的异构图谱中——**容量与上下文窗口完全解耦**。

- **11 种节点类型**（TASK/DIALOGUE/EPISODE/TOOL_CALL/TOOL_RESULT 等）× **7 种边类型**（关联/因果/时序/赫布等），将 Agent 运行中的所有信息结构化入图，**无压缩、无丢失**
- **冷热双路径存储**：近期活跃记忆驻留内存（热路径），历史记忆持久化至 LMDB + FAISS（冷路径），容量可达**数十万节点**
- **只检索不塞入**：每次 LLM 调用前，按可配置的 token 预算（如 2,000 token）精准提取最相关的记忆子图注入上下文，Agent 原生 prompt **完全不受影响**

> *对比：Mem0 受限于向量存储的扁平结构，祖龙的图结构让同等 token 预算下携带的信息密度提升 3-5 倍。*

#### 解决「记不准」：BFS 扩散检索 + 赫布学习

**核心机制**：不是"搜索关键词"，而是**"沿着关联链找到真正相关的记忆"**。

- **BFS 扩散检索（深度 3）**：从查询锚点出发，沿图谱边逐层扩散——用户提到"上次那个 bug"，系统不仅返回该 bug 记录（1 跳），还自动发现关联的代码文件、修复方案、负责人、甚至当时讨论的上下文（2-3 跳）。**这是图记忆对平面检索的碾压级优势**
- **赫布学习（Hebbian Learning）**：共同被检索的记忆节点自动加强关联权重——"经常一起被想起的记忆，就应该更紧密地关联"，模拟人脑的联想记忆机制，**用得越久图谱越精准**
- **冲突仲裁**：高相似度记忆自动检测矛盾，时间戳仲裁（新事实取代旧事实，但旧事实不删除，标记为历史版本 + 关联 `superseded_by` 边），保证 Agent **永远不会读到"过时但权重更高"的错误记忆**

> *对比：Mem0/Zep 的向量检索只能返回"语义相近"的文本片段，无法发现 2-3 跳之外的隐含关联，也无法自动加强高频记忆。*

#### 解决「记不久」：艾宾浩斯衰减 + 环境快照重评估

**核心机制**：记忆有"保质期"——**重要的越记越牢，过时的自然淡出，中断后可智能恢复**。

- **艾宾浩斯遗忘曲线衰减**：每条记忆节点维护访问频率和时间戳，长期不被访问的记忆自动降低优先级（权重衰减），避免陈旧信息干扰当前决策。同时，被赫布学习加强的记忆会**抵抗衰减**——重要且常关联的记忆"越用越新"
- **环境快照 + 重评估决策**：任务中断后恢复时，系统对比中断前后的环境快照（文件状态、上下文变量、工具状态），智能判断三种策略：
  - `RESUME`（环境未变，直接继续）
  - `REPLAN`（环境微变，调整计划继续）
  - `ABORT`（环境巨变，放弃并通知用户）
  - 这是**全市场唯一的闭环重评估能力**——竞品在中断后只能盲目继续或盲目重做
- **会话级绑定**：Web/IDE 会话窗口通过 `conversation_id` 直接绑定图谱根节点，新会话自动 BFS 扩散（深度 3）恢复上下文，**跨会话不丢失，跨项目不污染**

> *对比：Mem0/Zep 的记忆是只增不减的平面列表，没有衰减机制也没有中断恢复能力，记忆越多噪声越大。*

#### 附加防护：CircuitBreaker 智能熔断器

> *记忆解决"记住"的问题，熔断器解决"记住之后不乱来"的问题。*

CircuitBreaker 以中间件形式嵌入 Agent 工具调用链，**6 信号综合检测**（信息增益、上下文压力、空转、重复调用、工具震荡、资源消耗），GREEN→YELLOW→RED 三级状态机。在 YELLOW 阶段发出警告并建议策略调整，在 RED 阶段自动熔断并返回结构化诊断报告。**全市场唯一的多信号综合熔断方案**，比"最大步数截断"精准度高 4 倍。

#### 效果验证（内测数据）

| 指标 | 无记忆基线 | ZulongMemory 加持 | 提升 |
|------|-----------|------------------|------|
| **记不多** — 有效记忆容量 | ~8K token（受上下文窗口限制） | **数十万节点**（图谱独立存储，按需提取） | **10x+** |
| **记不准** — 关联记忆召回精度 | 平面检索仅 1 跳匹配 | **BFS 3 跳扩散 + 赫布加权排序** | 召回率 +65% |
| **记不久** — 跨会话上下文恢复率 | 0%（每次从零开始） | **87%**（会话绑定 + BFS 自动恢复） | 从 0 到 87% |
| 附加 — Agent 死循环率 | 22%（复杂任务） | **< 3%**（CircuitBreaker 拦截） | 降低 86% |
| 附加 — 集成后响应延迟增量 | — | **< 50ms**（热路径）/ **< 200ms**（冷路径） | 低于竞品 |

| **生态壁垒** | MCP Server 标准化接口，一旦 Agent 接入并积累记忆数据，迁移成本高（记忆图谱不可导出为平面格式） |
| **先发壁垒** | 图记忆赛道目前无主导者，12-18 个月的窗口期足以建立开发者社区和品牌认知 |
