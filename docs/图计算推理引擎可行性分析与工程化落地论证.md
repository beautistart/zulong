## 一、核心定位：白盒化LLM

### 1.1 本质关系

图计算推理引擎与LLM不是"不同范式"，而是"同一范式的不同实现"：

| LLM | 图计算推理引擎 |
|-----|---------------|
| 不透明的密集参数矩阵 → 黑盒推理 | 透明的记忆节点网络 → 白盒推理 |
| 神经元（不可解释） | 记忆节点（每个节点 = 一个可解释的概念/案例） |
| 权重矩阵（密集全参数） | 节点算子（每个算子 = 一个小型参数化函数） |
| Attention（全局O(n²)交互） | BFS路径规划（决定信号走哪条路） |
| 残差流 | 跨层直连边 |
| 位置编码（RoPE） | 动态路径地址编码 |

**关键区别不在计算能力，而在每个计算单元是否可解释、可独立修改、可增量学习。**

### 1.2 LLM机制的图架构等价映射

| Transformer机制 | 图引擎等价实现 | 实现方式 |
|----------------|---------------|---------|
| 残差流 | 节点旁路边直传 | `signal_out = signal_in + α·transform(signal_in)`，原始信号永不丢失 |
| Multi-Head Attention | 多语义探针并行BFS | 输入分解为因果/时序/空间等探针，每个探针独立BFS → 汇合 |
| 位置编码（RoPE） | 动态路径地址编码 | BFS路径中每个节点的ID hash + 深度 + 分支号 → 位置向量 |
| Layer Normalization | 节点级信号归一化 | 每个节点输出前做LayerNorm，防止信号尺度漂移 |
| 自回归生成 | 自回归BFS循环 | 知识子图BFS → 解码token → token embedding再注入 → 循环 |
| KV Cache | 路径缓存 | 已激活的BFS路径与中间状态缓存，避免重复计算 |
| FFN层 | 节点算子 | `W·x + b`，从节点语义内容推导的小型参数化函数 |

### 1.3 节点算子的本质

节点 = 一个小型参数化推理单元：

```
节点存储（无损、非量化）:
  content:  "匀速直线运动的牛顿第一定律"
  cases:    [案例1: 太空中的物体..., 案例2: 冰面上的冰壶...]
  facts:    ["不受外力则保持运动状态", "惯性是物质的固有属性"]

节点算子（参数化函数）:
  W(64×64): 从节点语义内容推导的变换函数
  作用: 当信号经过时，把与"牛顿第一定律"相关的维度放大，无关维度抑制，注入本节点知识

计算过程:
  signal_in → 相关性检测(cos) → 算子变换(W·x+b) → 残差保护 → signal_out
```

等价于Transformer的FFN层：两者都是"对信号做非线性变换以注入知识"，区别是LLM的FFN是密集全参数（每个token都过同一个FFN），图引擎是稀疏激活（只有相关概念的节点参与计算）。

## 二、理论基础评估

### 2.1 有扎实理论支撑的部分

| 机制 | 理论依据 | 对应阶段 |
|------|---------|---------|
| GNN消息传递范式 | Kipf & Welling 2017, GraphSAGE 2017，成熟范式 | Phase 1-2 |
| 稀疏激活 | 神经科学稀疏分布式表示，HTM理论 | 性能可行性 |
| 赫布学习 | Hebb 1949，LTP长时程增强 | Phase 4 |
| 艾宾浩斯衰减 | Ebbinghaus 1885，经典心理学实验 | Phase 4 |
| alpha混合保护旧能力 | EWC弹性权重巩固 Kirkpatrick 2017 | Phase 3.5 |
| 小世界网络拓扑 | Watts & Strogatz 1998 | Phase 3 |

### 2.2 需要Phase 1实验验证的关键假设

| 假设 | 风险 | 验证方法 |
|------|------|---------|
| 64×64矩阵编码能力足够 | 高 | Johnson-Lindenstrauss引理估算64维有效区分容量；信息论上界测试 |
| 残差+LayerNorm可对抗多跳信号衰减 | 高 | 3/5/10跳信号保留率测量(cos(signal_0, signal_N)) |
| 交叉激活超线性放大不会导致信号爆炸 | 中 | 多探针汇合稳定性测试 |
| 语义embedding推导的算子初始化足够好 | 中 | 与随机初始化对比推理质量 |

### 2.3 总体结论

> 图计算推理引擎作为LLM的白盒化重构，理论基础成立。所有使Transformer成功的核心机制（残差流、位置编码、多头注意力、层归一化、自回归解码）都有对应的图架构等价实现。两者的计算本质相同（参数化算子对信号做非线性变换），区别在于图架构提供了可解释性、增量学习和稀疏激活等结构性优势。真正的挑战不在理论，而在工程。

## 三、动态路径地址架构（核心创新）

### 3.1 固定拓扑的致命问题

固定拓扑（节点有固定地址/层级）会导致：
- **一词多义无法处理**："苹果"固定在水果分支下，无法同时表示"苹果手机"
- **增量学习被卡死**：新增节点需要重新规划整个地址体系
- **图退化为树/网格**：失去图结构的灵活性优势

### 3.2 动态路径方案：地址是遍历属性，不是节点属性

```
节点 = {id, content, cases, operator}     ← 节点无地址
边   = {(苹果,水果): 0.9, (苹果,科技): 0.7, (苹果,红色): 0.6}

BFS从"我吃了个苹果"出发:
  路径: 吃→食物→水果→苹果
  动态地址: /食物/水果/苹果

BFS从"苹果发布了新手机"出发:
  路径: 手机→科技→公司→苹果
  动态地址: /科技/公司/苹果

同一个节点，不同语境下有不同的路径地址
```

### 3.3 类比：文件系统的软链接模型

| 文件系统 | 图引擎 |
|---------|--------|
| 文件（inode） | 节点（唯一物理存储） |
| 符号链接 | 边（多条路径可达同一节点） |
| 路径字符串 | 动态路径地址 |
| 访问方式决定含义 | 遍历路径决定语义 |

### 3.4 路径即上下文（解决一词多义）

```
路径A: /物理/力学/牛顿定律/力 → 位置编码含"物理"语义 → 输出"力学中的力"
路径B: /社会/政治/权力结构/力 → 位置编码含"权力"语义 → 输出"权力/影响力"
路径C: /军事/战略/武力/力     → 完全不同的输出

→ 节点算子是同一个 W
→ 但输入信号已包含路径上下文
→ 相同算子 + 不同上下文 = 不同输出
→ 数学等价: Transformer的 output(token) = f(token, context)
```

### 3.5 路径级Beam Search（防止路径爆炸）

```
问题: 500入口 × 10邻居 × 3跳 = 500,000条路径 → 内存/计算扛不住

解决: 路径级Beam Search，只保留top-50条最有价值路径

路径质量评分 = 信号强度×0.4 + 路径语义连贯性×0.3 + 新颖性×0.3
  - 信号强度: 当前信号的L2范数
  - 语义连贯性: 相邻节点间embedding相似度的均值
  - 新颖性: 避免重复走相同区域
```

### 3.6 路径沉淀（从临时到永久的快捷通路）

```
临时路径 → 高频统计 → 路径沉淀

例: /物理/力学/牛顿定律/力 被走200次
  → 固化为"快捷路径": 入口节点"物理"直接建强化边到"力"
  → 相当于人脑"自动化回路": 反复走同一条路后形成快捷通路

快捷路径 ≠ 固定地址:
  只是一条权重更高的边
  BFS仍然可以走其他路径到达同一节点
  快捷路径是优化，不是约束
```

### 3.7 增量学习：新节点即插即用

```
新增"量子纠缠"节点:
  1. 创建节点{id, content, operator}
  2. bge-small计算embedding → FAISS搜索 → 自动建边
  3. 完成，不需要任何地址重新分配

BFS时自然经过新节点 → 新节点立即参与推理
→ 增量学习 = 添加节点 + 添加边，零重构成本
```

## 四、工程化落地：逐阶段挑战与解决方案

### Phase 1：算子MVP验证（2-3周）

#### 挑战1：算子初始化

**问题**：随机矩阵导致信号爆炸/消失；全单位矩阵等于没算。

**解决方案：语义embedding推导的残差初始化**
```python
e_768 = bge_small.encode(node.content)        # 768维embedding
e_64 = Linear(768, 64) @ e_768                # 投影到64维
W = I_64 + alpha * np.outer(e_64, e_64)       # 残差初始化
# 残差连接保证信号不爆炸，外积方向对齐节点语义
```

#### 挑战2：多跳信号衰减

**问题**：矩阵连乘导致奇异值指数增长/衰减（同深度RNN问题）。

**解决方案：节点级LayerNorm + 旁路残差**
```python
def node_forward(node, signal_in):
    transformed = node.W @ signal_in + node.bias
    normalized = layer_norm(transformed)
    signal_out = signal_in + node.alpha * normalized  # 残差连接
    return signal_out
# 经过N跳后: signal_N = signal_0 + α₁·norm₁ + α₂·norm₂ + ...
# 原始信号signal_0永远保留
```

**验证指标**：
- 3跳信号保留率 >90%（cos(signal_0, signal_3)）
- 5跳信号保留率 >75%
- 10跳信号保留率 >50%

### Phase 2：算子BFS推理引擎（3-4周）

#### 挑战3：多探针语义分解精度

**问题**：语义分解本身需要理解能力——循环依赖。

**解决方案：两阶段探针生成（纯本地，<15ms）**
```
阶段A（<10ms）: bge-small编码 → 规则分句 → 3-5个探针向量
阶段B（<5ms/探针）: 每个探针 vs FAISS热区索引 → top-3入口节点 → 合并去重
```

#### 挑战4：FAISS热区冷启动

**解决方案：三阶段热区演化**
1. 冷启动: LLM标记核心概念 + Hub节点自动标记 → 构建初始FAISS索引
2. 预热期(前1000次): 统计实际访问频率 → 每小时更新索引
3. 稳定期: 热区趋于幂律分布 → 更新频率降至每天

#### 挑战5：交叉激活信号冲突

**解决方案：注意力融合（非简单相加）**
```python
def cross_activation_merge(signals, node):
    relevance = [cos(s, node.semantic_vector) for s in signals]
    weights = softmax(relevance / temperature)
    merged = sum(w * s for w, s in zip(weights, signals))
    amplified = merged * (1 + 0.3 * log(len(signals)))  # 超线性放大
    return layer_norm(amplified)
```

#### 挑战6：与现有L2推理引擎集成

**解决方案：正交推理路径 + 融合门控**
- 新增`graph_reason`工具供FC循环调用
- 融合门控: 图置信度高→直出；低→fallback到LLM；中间→融合
- 现有FC循环、TaskGraph、CircuitBreaker完全不改造

### Phase 3：LLM自动化教学管线（2-3周）

#### 挑战7：LLM输出结构化可靠性

**问题**：500-800个节点 × 20%出错率 = 100-160个坏节点。

**解决方案：四层校验管线**
1. JSON Schema强制校验（Pydantic，失败自动重试3次）
2. 内容非空+长度校验（content>50字符，key_facts≥3）
3. 交叉一致性校验（节点vs邻居embedding相似度>0.3）
4. 推理链验证（S5阶段自动测试→失败路径回溯→定向修复）

#### 挑战8：建边陷入分类树

**解决方案：强制混合批次 + 跨域建边指令**
- 每批30节点来自尽可能多的不同维度
- Prompt强制要求至少5对跨领域关联
- 自动校验: 平均最短路径≤5跳，聚类系数≥0.3，HIERARCHY边≤10%

#### 挑战9：API成本控制

**解决方案：分级LLM策略**
- S1-S4: DeepSeek-V3（¥0.5/M token）
- S5测试: 图引擎推理（零成本） + DeepSeek判分
- 总成本: <¥10

### Phase 3.5：蒸馏框架（3-4周）

#### 挑战10：行为采样覆盖率

**解决方案：分层采样 + 不确定性驱动**
- Layer 1: 节点级覆盖（5000条，每节点≥10条）
- Layer 2: 边级覆盖（3000条，高频遍历top-300条边）
- Layer 3: 不确定性驱动（2000条，置信度最低的场景）
- Layer 4: 跨域组合（1000条，随机组合不同社区）

#### 挑战11：少样本算子重拟合过拟合

**解决方案：正则化+先验约束的岭回归**
```python
W_new = solve(X^T X + αI, X^T Y)  # 岭回归
beta = min(0.5, n_samples / 50)    # 样本越多，更新幅度越大
W_final = beta * W_new + (1 - beta) * W_old
```

### Phase 4：三级跃迁与闭环建边（5-6周）

#### 挑战12：六维沉淀评估权重确定

**解决方案：无监督自适应权重 + LLM校准**
1. 冷启动: 等权重 w1=...=w6=1/6
2. 1000次推理后: 基于方差自适应（高方差维度降权）
3. 10000次推理后: 基于路径贡献度校准
4. 可选: LLM校准top/bottom节点

#### 挑战13：赫布权重无限增长

**解决方案：归一化+竞争抑制**
- 赫布权重除以邻居数量（归一化）
- 弱节点相对强邻居逐渐退让（竞争抑制）
- 上限钳制（MAX_HEBBIAN_WEIGHT）

#### 挑战14：实时自动建边延迟

**解决方案：异步批量建边**
- 实时路径(<20ms): FAISS top-3建弱边，不阻塞对话
- 后台路径(<500ms): 完整FAISS top-10 + 精确权重，异步补充

### Phase 5a：语义插槽直出（3周）

#### 挑战15：模板填充泛化性

**解决方案：多层级模板 + 语义匹配填充**
- 精确匹配: BFS上下文有对应值 → 直接填充conclusion_template
- 案例适配: 无精确匹配 → 从concrete_examples找最相似案例 → 适配

### Phase 6-7：分片优化与ARM部署（5-7周）

#### 挑战16：时间分片→语义社区分片迁移

**解决方案：在线渐进迁移（双写期24h + 切换期72h）**
- 跨社区边>30% → 重新运行Louvain调整resolution参数
- 目标: 跨社区边<15%

#### 挑战17：RK3588 16GB内存预算

**解决方案：分级内存管理 + 模型分时复用**
```
优先级1（永不释放）: 语言子图FP16 5.9GB + 桥接192KB + 系统2GB
优先级2（LRU淘汰）: 知识子图温区分片 最大2GB
优先级3（按需加载）: bge-small/SenseVoice/Kokoro 分时复用
→ 峰值: 5.9+2+0.244+2 = 10.1GB ← 安全（14GB可用）
```

## 五、贯穿全程的系统性挑战

### 5.1 端到端可测试性

**问题**：各Phase环环相扣，最终效果不好时难以定位。

**解决方案：逐层隔离测试**
- Phase 1基准: 纯算子测试（信号保留率）
- Phase 2基准: 推理链路测试（BFS路径质量，可用随机算子）
- Phase 3基准: 图结构测试（连通性/小世界特性，不依赖算子）
- Phase 4基准: 动态行为测试（跃迁/衰减/建边行为，不依赖推理质量）

### 5.2 与现有系统兼容性

**原则：纯增量扩展，零修改现有接口**
- NodeProperties新增可选字段（默认值兼容）
- 新增独立模块`zulong/memory/graph_compute/`
- 算子层通过装饰器模式接入（OperatorEnhancedGraph）
- 即使图计算引擎完全移除，现有系统不受影响

## 六、图架构的独特优势（LLM做不到）

| 优势 | LLM | 图引擎 |
|------|-----|--------|
| 可解释性 | 70B参数不可解释 | 每个节点代表明确概念，可追踪推理路径 |
| 增量学习 | 灾难性遗忘 | 新增节点/边，不动旧结构 |
| 单点修正 | 无法修正单个知识点 | 修改一个节点的案例/算子即可 |
| 知识溯源 | 不知道知识从哪来 | 每个节点记录来源（LLM教师/用户对话/自验证） |
| 稀疏激活 | 70B参数全量计算 | 每次只激活~500个相关节点 |
| 永不遗忘 | 微调覆盖旧知识 | 沉淀节点永久保护 |
| 可审计 | 黑盒 | 完整推理路径可视化 |
| 有机增长 | 训练后能力固定 | 使用中持续积累，能力单调增长 |

## 七-A、64×64维度能力边界与计算委托机制

### 维度能力评估

LLM用4096-8192维做数学，但其中仅~50维有效编码数学信息（其余被语法/风格/世界知识瓜分）。图引擎64维全部用于数学，有效编码反而更高。LLM数学能力的瓶颈不在维度，而在分布式表示不擅长精确计算——图引擎同样如此，**解决方案也相同：委托专用计算工具**。

| 推理类型 | 64×64是否够用 | 原因 |
|----------|-------------|------|
| 符号推理（用什么公式、什么顺序） | ✅ 够用 | 每个节点专注单一概念，64维全部编码该概念 |
| 线性关系（F=ma, V=IR） | ✅ 够用 | 线性变换是64×64矩阵的原生能力 |
| 简单非线性（E=½mv²） | ✅ 够用 | 残差初始化可编码非线性修正 |
| 多步公式联立（3-5跳BFS） | ✅ 够用 | 多节点串联，等效320维编码空间 |
| **高精度数值计算** | ❌ 不够 | 64维FP32无法编码10位以上数值精度 |
| **复杂符号运算** | ❌ 不够 | 需数十步符号变换，超出单节点容量 |

### 三层分离架构

```
图引擎的推理 = "想"（用什么公式、什么顺序、什么条件）→ 64×64足够
精确计算     = "算"（具体数值运算）                     → 委托计算器
语言表达     = "说"（生成自然语言文本）                 → 语言子图/LLM

类比人类物理学家:
  大脑: 决定用牛顿第二定律、分析受力、列方程 → "推理"（图引擎64×64）
  计算器: 计算 9.8×5.3×sin(30°) = 25.97     → "计算"（委托工具）
  嘴巴: 向别人解释解题过程                    → "表达"（语言子图）
```

### 计算委托触发机制与架构

```
BFS推理过程中，节点算子检测到以下信号时触发委托:
  信号1: 节点标记 has_numerical_computation=True
  信号2: 输入信号中数值密度超标(多个维度绝对值>阈值)
  信号3: 节点案例中包含"需要计算"的历史案例

ComputeDelegateLayer:
  - 符号运算: 本地SymPy(不定积分/微分/方程求解)
  - 数值运算: Python math/numpy(浮点运算)
  - 单位换算: 本地pint库(物理量单位自动转换)
  - 线性代数: numpy.linalg(矩阵运算)

延迟预算:
  符号运算(SymPy): ~10-100ms
  数值运算(eval):  ~0.1ms
  单位换算(pint):  ~1ms

内部计算委托 vs 外部工具:
  内部计算委托: SymPy/numpy/pint，图引擎内部直接调用，不走FC循环
  本质: 推理基础设施的一部分，如同CPU的浮点运算单元
  外部工具(搜索/代码/文件等): 由系统层FC循环提供，图引擎不感知
  严格区分: 内部计算是推理必要能力，外部工具是信息获取能力
```

### 验证标准
- 触发正确性: 需精确计算100%触发委托，纯符号推理0%误触发
- 委托延迟: 数值<1ms，符号<100ms，单位<5ms
- 结果精度: 与Python精确计算一致(float64精度)
- 端到端影响: 含委托的推理总延迟 < 无委托推理延迟 + 200ms

## 八、动态路径架构 vs 固定拓扑 vs Transformer 对比

| 维度 | Transformer | 固定拓扑图 | 动态路径图（最终方案） |
|------|-------------|-----------|---------------------|
| 地址 | 位置编码（固定注入） | 节点属性（硬编码） | 遍历属性（运行时构建） |
| 位置编码 | RoPE（每层重注入） | 固定 | 路径依赖（同一节点不同编码） |
| 一词多义 | 上下文attention自动区分 | 需多个节点 | 同一节点，路径区分 |
| 增量学习 | 需重新训练 | 需重新规划地址 | 即插即用 |
| 增长方式 | 不可能（训练后固定） | 需架构师重设计 | 有机增长，自然扩展 |
| 信息路由 | 动态（attention权重=f(输入)） | 固定（拓扑决定） | 半动态（BFS路径+算子响应） |
| 可解释性 | 黑盒 | 可解释 | 可解释+路径可视化 |

## 九、核心设计原则总结

1. **白盒等价原则**：所有LLM成功机制都应且都可以在图架构中等价实现
2. **动态路径原则**：地址是遍历属性而非节点属性，支持一词多义和增量学习
3. **残差保护原则**：原始信号永远直传不丢失，每跳只追加修正量
4. **稀疏激活原则**：每次推理只激活~500个相关节点，远小于LLM全量计算
5. **渐进替代原则**：LLM仅参与冷启动，日常运行零依赖
6. **沉淀不可逆原则**：已验证知识一旦沉淀，永不衰减/遗忘/降级
7. **增量扩展原则**：纯增量扩展，零修改现有接口，向后完全兼容
8. **三层分离原则**：推理(64×64图引擎) / 计算(委托SymPy/numpy) / 表达(语言子图)——各司其职，不互相替代
9. **相关链路优先原则**：当前问题越相关，激活链路路由优先级越高；所有权重增益有界
10. **非固定链路数原则**：激活链路控制不以固定条数为上限，`8`仅可作为证据路径展示/审计默认值
