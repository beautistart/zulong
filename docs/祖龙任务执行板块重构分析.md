# 祖龙任务执行板块重构分析

> 基于对祖龙实际代码和 Claude Code / Devin / Cursor(Codex) / Cline / OpenHands 的深度对比研究

---

## 一、当前架构诊断

### 1.1 执行流程一览

```
用户输入 → session_start → _run_fc_loop()
                              │
                              ├─ ① 初始化(1个 status_update "initializing")
                              ├─ ② 获取记忆上下文（内部完成，不告诉用户）
                              ├─ ③ 自动创建 TaskGraph（内部完成，不告诉用户）
                              │
                              └─ ④ while True: ← 从此入口到任务完成，中间是黑洞
                                   │
                                   ├─ 调模型 → 等2s心跳
                                   ├─ 有工具调用 → 执行(内部/远程)
                                   │     └─ CB检测 → BFS扩散 → continue
                                   └─ 无工具调用 → 8层安全网 → done/continue
```

**核心问题**：步骤②③④对用户来说都是黑盒。用户只看到"思考中…"，不知道记忆召回了什么、计划是什么、每一步在做什么、卡在哪、为什么卡。

### 1.2 当前状态管理

- **FCLoopState**: TypedDict（15个字段），可变字典在节点间传递
- **IDEFCState**: Dataclass，支持序列化
- **should_terminate**: 字符串（约15种终止原因散落各处），无统一枚举
- **事件系统**: `UnifiedProtocol` 有30+种消息类型，但FC循环核心自身不使用事件驱动

### 1.3 缺失的6个标准事件

| 标准事件 | 当前状态 | 建议补充位置 |
|---------|---------|------------|
| `memory.recalled` | ❌ | `_maybe_run_bfs()` 返回激活结果时广播 |
| `plan.proposed` | ❌ | `_auto_create_task_plan()` 创建完TaskGraph后广播 |
| `step.started` | ❌ | `task_mark_status` 标记in_progress时广播 |
| `tool.started` | ❌ | `_exec_internal()` 和远程工具推送前发送 |
| `diff.ready` | ❌ | `_auto_anchor_on_write()` 完成后广播 |
| `approval.required` | ❌ | `_exec_tools_async` 中检测requires_approval时暂停 |

## 二、竞品能力映射

### 2.1 学 Claude Code 的可控性

| Claude Code 能力 | 祖龙现状 | 具体改哪里 |
|---|---|---|
| 6级权限模式 | 完全缺失 | `_exec_tools_async()` 中增加requires_approval检查 |
| 每步操作前说人话 | 模型直接调工具 | `_call_model()` prompt中增加中文意图说明要求 |
| Permission Dialog | execute_command有参数但没用 | `tool_request`消息增加requires_approval字段 |
| Checkpoint/Rewind | 无 | 写文件前difflib快照，存到IDEFCState.checkpoints |
| Protected Paths | 无 | IDEToolRegistry增加路径白名单检查 |

### 2.2 学 Devin 的开场评估

| Devin 能力 | 祖龙现状 | 具体改哪里 |
|---|---|---|
| 项目分析摘要 | 无 | 新增`project_analyzer.py`，在`_run_fc_loop()`中增加评估阶段 |
| AI设置建议 | 无 | 读package.json/requirements.txt等自动检测 |
| Interactive Planning | TaskGraph自动创建但不展示 | `_auto_create_task_plan()`后推送plan_proposed |
| 引用追溯 | 无 | 记忆检索上下文携带来源标记 |

### 2.3 学 Cursor/Codex 的后台沙箱

**关键立场**：祖龙主系统不能跑在Docker里，否则文件路径映射会让小白用户抓狂。正确做法是分层安全：

| 操作类型 | 执行环境 | 安全控制 |
|---------|---------|---------|
| 读文件、搜索、记忆检索 | 宿主机直接执行 | 无 |
| 写文件、修改代码 | 宿主机+Diff快照 | 写前备份，可回滚 |
| 执行项目测试 | 宿主机subprocess | 超时+输出截断 |
| 执行用户提供的未知代码 | 可选Docker沙箱 | 完全隔离，手动开启 |

### 2.4 学 Cline/OpenHands 的开源结构

| 开源项目 | 最值得借鉴 | 具体机制 |
|---------|----------|---------|
| OpenHands Event Stream | 不可变事件流+因果追踪+可回放 | `openhands/events/` 整个目录设计 |
| OpenHands 状态机 | 显式execution_status枚举 | RUNNING→WAITING_USER→BLOCKED→FINISHED |
| OpenHands Agent无状态 | Agent.step(history)→next_event | 纯函数，方便测试和替换 |
| Cline TaskPresentationScheduler | 流式输出优先级调度 | 第一个token立即推，后续缓冲批量推 |
| Cline CheckpointTracker | git worktree文件快照 | 每次写文件前备份 |
