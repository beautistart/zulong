# 注意力增量更新代码调整记录（2026-06-29）

## 目标

把动态注意力从“每轮实时塞状态”收敛为“按需、独立、增量注入/推送”：

- 当前 active context token 估算不实时推给模型；只有触发 yellow/red 阈值后，随阈值提示注入百分比。
- FC 循环轮次不作为常规 LLM 输入；只在后台诊断、前端状态或阈值恢复上下文中作为附属字段。
- 当前注意力模式（global / single_chain / focus）只在变化时重新注入。
- 上下文窗口压力百分比和比率不实时注入；只在 yellow/red 阈值触发后注入阈值归一百分比。
- LLM 是否参与注意力模式选择，只在阈值触发时提示并推送选择结果。
- MemoryGraph BFS 扩散节点数只在发生记忆检索/BFS 时推送，没有检索时不刷新 0 值。
- 导航地图只在真实变化时注入；同位置、同模式、同触发原因不重复注入。
- 各更新项独立判断，不再依赖一整个上下文块的 hash 校验。

## 注入规则

### 1. 注意力模式

代码位置：

- `zulong/ide/ide_fc_runner.py`：`last_llm_injected_attention_mode`
- `zulong/l2/inference_engine.py`：`_last_attention_mode`

规则：

- 第一次为 `global` 时不额外注入模式更新。
- 模式从旧值变为新值时，设置 `include_mode_update=True`。
- 渲染层只在 `include_mode_update=True` 时输出“注意力模式更新”段。

### 2. 压力百分比

代码位置：

- `zulong/ide/ide_fc_runner.py`：`last_llm_injected_pressure_tier`
- `zulong/l2/inference_engine.py`：`_last_attention_tier`
- `zulong/l2/fc_runner.py`：`pressure_stage`

规则：

- green 状态不注入压力百分比。
- 只有 `pressure_tier in {"yellow", "red"}` 且 tier 发生变化时，设置 `include_pressure_update=True`。
- 注入给模型的是阈值预算归一后的百分比，即“阈值预算 = 100%”，不是原始窗口占比。
- 前端推送中保留 `context_pressure` / `trigger_context_pressure` 等必要字段，但不推 `raw_context_pressure`、`threshold_budget_pressure`、`visible_context_pressure`、`registered_context_pressure` 这类实时噪声字段。

### 3. LLM 注意力选择

代码位置：

- `zulong/l2/inference_engine.py`：`_send_attention_update(...)`
- `zulong/ide/ide_fc_runner.py`：压力引导和受限恢复段

规则：

- LLM 注意力选择只在 yellow/red 阈值触发时进入提示。
- 前端只在阈值触发下推送：
  - `llm_selection_enabled`
  - `last_selection_switched`
  - `last_selection_mode`
  - `last_selection_reason`
- 普通轮次不把“LLM 是否参与选择”作为实时状态刷新。

### 4. MemoryGraph 与 BFS

代码位置：

- `zulong/l2/attention_context_retrieval.py`：`should_include_memory_context_for_turn(...)`
- `zulong/ide/ide_fc_runner.py`：`_maybe_run_bfs(...)`
- `zulong/l2/inference_engine.py`：BFS telemetry diff

规则：

- 只有以下条件之一成立时检索/注入 MemoryGraph 上下文：
  - 工具预测或上下文 bundle 显示需要记忆。
  - 预测工具包含 `recall_memory`、`read_memory_node`、`save_memory_note`、`discover_related` 等记忆工具。
  - 用户文本包含“记忆 / 历史 / 上次 / previous / recall”等记忆线索。
  - 压力阈值触发或 red 受限恢复。
- 没有记忆检索时，不推送 `bfs_activated_count=0` 之类的实时状态。
- 发生记忆检索或 BFS seed 存在，且计数变化时，才推送：
  - `retrieved_memory_count`
  - `bfs_seed_count`
  - `bfs_activated_count`

### 5. 导航地图

代码位置：

- `zulong/ide/ide_fc_runner.py`：`last_navigation_map_state`
- `zulong/l2/attention_context_retrieval.py`：`include_navigation_map`

规则：

- 导航地图只在压力引导、压力恢复、显式注意力切换等需要重新定位时注入。
- 判断状态由以下字段组成：
  - `graph_id`
  - `mode`
  - `focus_node_id`
  - `reason`
- 状态不变时不重复注入。
- 注入后记录 `last_navigation_map_state`，下一轮用于差量判断。

## 前端 attention:update 差量字段

`attention:update` 现在按字段独立判断，不再把整包当作实时心跳。

会推送的典型字段：

- 模式变化：`mode`、`focus_node_id`、`focus_address`
- 阈值变化：`pressure_tier`、`budget_usage`、`trigger_budget_usage`、`pressure_threshold_medium`、`pressure_threshold_high`
- 记忆检索变化：`retrieved_memory_count`、`bfs_seed_count`、`bfs_activated_count`
- 导航地图变化：`navigation_map_injected`、`navigation_map_reason`、`active_context_item_count`

不会作为常规实时字段推送：

- active context token 估算的每轮值
- 原始上下文压力百分比/比率
- FC 循环轮次作为模型输入
- 未发生检索时的 BFS 0 值
- 未变化的导航地图状态

## 压力两段式行为

代码位置：

- `zulong/l2/fc_runner.py`
- `zulong/ide/ide_fc_runner.py`

行为：

1. 第一次达到 yellow/red 阈值：只注入动态注意力引导，让 LLM 选择模式。
2. 如果后续仍为 red：进入受限恢复，只保留注意力切换、便签、标签、记忆落盘等恢复能力工具。
3. red 恢复不再每轮重置现场保存状态，避免形成“压力 RED -> 强制保存 -> 再 RED -> 再保存”的循环。

## 后续维护原则

- 不要重新引入“每轮全量 attention 状态注入”。
- 不要用 hash 作为注意力增量更新的主门禁；应按字段语义独立判断。
- 新增 telemetry 字段前，先判断它是否是模型决策必要输入；如果只是诊断字段，应留在日志或前端，不进入 LLM active context。
- yellow/red 阈值是模型注入边界；green 下只保留必要任务上下文，不推压力状态。
- MemoryGraph 检索是按需行为；没有记忆需求时不要为了刷新计数而检索。
